# Version 3.0.0

## Migrating from 2.1.1

### Fallible conversions

Several conversions that could panic now implement `TryFrom`.
Replace `.into()` with `.try_into()?` when the destination type is known,
or use one of the explicit forms below.

| Destination   | Input                              | 3.0 API                        |
|---------------|------------------------------------|--------------------------------|
| `Digit`       | `char`, `i8`                       | `Digit::try_from(input)?`      |
| `Ternary`     | `&str`, `String`                   | `Ternary::try_from(input)?`    |
| `Tryte<N>`    | `&str`, `String`, `i64`, `Ternary` | `Tryte::<N>::try_from(input)?` |
| `Ter40`       | `i64`, `Ternary`                   | `Ter40::try_from(input)?`      |
| `i64`         | `Ternary`, `Tryte<N>`              | `i64::try_from(input)?`        |

Numeric conversions from `Ternary` and `Tryte<N>` to `i64` also accept
borrowed values. Existing explicit constructors such as `Ternary::parse`
remain available when invalid input should panic.

`ParseTernaryError` is now an enum. Its `InvalidCharacter` variant
contains the character and its UTF-8 byte offset. Parsing a `Tryte<N>`
returns `ParseTryteError`, which distinguishes invalid input (`Parse`)
from a value that exceeds the word's range (`Conversion`).

### Arithmetic and overflow

| Type       | Behavior in 3.0                                                                                                                       | What to change                                                                                                                          |
|------------|---------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------|
| `Ternary`  | Binary arithmetic operates directly on arbitrary-width values and returns canonical digits.                                           | If a result needs leading zeros, apply `with_length(width)` before formatting. Use `checked_to_dec()` when the result may exceed `i64`. |
| `Tryte<N>` | `+`, `-`, and `*` wrap modulo `3^N`. `/` performs signed integer division, truncating toward zero.                                    | Use `checked_add`, `checked_sub`, or `checked_mul` to detect overflow. Use `checked_modular_div` for modular division.                  |
| `Ter40`    | Constructors enforce the signed 40-trit range. Arithmetic operators panic on overflow, including when the result still fits in `i64`. | Use `Ter40::try_from` for input and `checked_*` methods for arithmetic that may exceed the range.                                       |

For example, a two-trit word has range `−4..=4`:

```rust
use balanced_ternary::Tryte;

type Word = Tryte<2>;
let one = Word::from_i64(1);

assert_eq!(Word::MAX + one, Word::MIN);
assert_eq!(Word::MAX.checked_add(one), None);
```

### Ordering compact storage

`DataTernary` no longer implements `Ord` or `PartialOrd`. If a collection
was sorted by numeric value, use `values.sort_by_cached_key(|v| v.to_ternary())`.
For numeric keys in a `BTreeMap` or `BTreeSet`, use `Ternary`.

`DataTernary` equality and hashing still compare the complete stored chunk
sequence. Converting to a numeric key can therefore merge entries that
differ only by leading zero chunks.

## New capabilities

- `Ternary::div_rem()` computes the quotient and remainder together.
  `%` is available for borrowed `Ternary` operands.
- Ordinary base-3 conversion supports arbitrary precision.
  `Ternary::try_from_unbalanced()` accepts an optional ASCII sign.
- `Tryte<N>` supports widths above 40 trits. A zero-width word represents
  only zero. Bounded conversions accept redundant leading zeros when the
  numeric value fits.
- `Tryte<N>` and `Ter40` expose the outgoing trit through
  `each_zip_carry_full()`. The `DigitOperate` trait keeps its existing
  signatures.

## Fixes and performance

- Corrected single-trit subtraction modulo three, conversion at `i64::MIN`,
  and trimming of values wider than `i64`.
- Added reproducible timing and allocation benchmarks. Across the tested
  widths of 16, 40, 128, and 512 trits, `DataTernary` encoding and both
  decoding modes each used one allocation and zero reallocations.
- Added CI coverage for feature combinations in debug and release,
  README doctests, and embedded `no_std` builds.
