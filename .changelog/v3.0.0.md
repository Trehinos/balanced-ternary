# Version 3.0.0

|                  |                           |
|------------------|---------------------------|
| Label            | Major arithmetic overhaul |
| Type             | Major release             |
| Publication date |                           |

## Fixed

- **R01:** Fixed `Digit` subtraction modulo 3.
- **R02:** Fixed `Ternary::checked_to_dec()` overflow handling,
  including the `i64::MIN` boundary.
- **R03:** Removed the unnecessary `i64` conversion from
  `Ternary::trim()`.
- **R04:** Enforced the signed 40-trit range in `Ter40`
  constructors and arithmetic operations.

## Added

### Fixed-width arithmetic (R04–R05)

- Added checked arithmetic methods for `Ter40`:
  `checked_add()`, `checked_sub()`, `checked_mul()`,
  and `checked_div()`.
- Added wrapping, checked, overflowing, and saturating
  arithmetic methods for `Tryte<N>`.
- Added `add_with_carry()` and `sub_with_carry()`
  for fixed-width arithmetic.
- Added `each_zip_carry_full()` to `Tryte<N>` and `Ter40`,
  exposing the outgoing carry without changing
  the `DigitOperate` trait.
- Added `checked_modular_inverse()` and
  `checked_modular_div()` for modular arithmetic
  modulo `3^N`.

### Arbitrary-precision arithmetic (R06)

- Implemented native arbitrary-precision addition
  and subtraction for `Ternary`.
- Implemented arbitrary-precision multiplication
  directly on balanced ternary digits.
- Implemented arbitrary-precision signed integer
  division using long division in base 3.
- Added the `%` remainder operator for `&Ternary`.
- Added `Ternary::div_rem()` to compute the quotient
  and remainder in a single operation.
- Added normalization of arithmetic results,
  removing leading zeros and preserving canonical zero.

### Tests

- Added exhaustive arithmetic tests for small
  balanced ternary values and fixed-width words.
- Added boundary tests for `i64` and 40-trit values.
- Added tests for arithmetic on numbers exceeding
  native integer limits, including 1000+ trit values.
- Added tests for modular inversion and division.
- Added tests for negative operands, division by zero,
  outgoing carries, and noncanonical representations.

## Changed

### `Tryte<N>` arithmetic

- Addition, subtraction, and multiplication now
  wrap modulo `3^N`.
- Division uses signed integer division, truncating
  toward zero.
- Wrapping, overflowing, and saturating division
  helpers are retained for API consistency.
- Modular division is exposed through separate,
  explicitly named methods.

### `Ternary` arithmetic

- Arithmetic operators no longer convert operands
  to `i64`.
- Addition, subtraction, multiplication, and division
  now operate directly on digit representations.
- Arithmetic is no longer limited by native integer
  ranges.
- Division truncates toward zero, and the remainder
  has the sign of the dividend.
- Arithmetic results use a canonical representation,
  independently of the original operand padding.

## Performance

- Eliminated intermediate `i64` conversions from
  `Ternary` arithmetic.
- Implemented linear-time addition and subtraction
  over balanced ternary digit sequences.
- Implemented schoolbook multiplication with
  O(n*m) complexity.
- Implemented long division with O(n*m) complexity.
- Reduced unnecessary intermediate allocations
  in fixed-width arithmetic.
- Preserved `#![no_std]` compatibility.

### R07 — Allocation and Conversion Optimizations

#### `Tryte<N>`

- Replaced intermediate `Ternary` conversions in
  `to_i64()` and `from_i64()` with direct digit processing.
- Optimized bitwise AND, OR, and XOR to operate directly
  on fixed-size digit arrays.
- Removed intermediate `Ternary` and `String` allocations
  from `Display`.
- Preserved fixed-width representation and arithmetic
  semantics.

#### `Ter40`

- Added direct decoding of the internal `i64` value into
  a fixed-size 40-trit array.
- Optimized `digit()` to extract trits without allocation.
- Optimized `to_digits()` and `to_ternary()` to avoid
  unnecessary intermediate representations.
- Removed intermediate allocations from `Display`.
- Preserved the exact 40-trit representation, including
  leading zeros.

#### `Ternary`

- Optimized `get_digit()` from O(n) to O(1).
- Removed intermediate `String` allocation from `Display`.
- Improved allocation efficiency in `parse()`,
  `with_length()`, `concat()`, and `to_string_repr()`.
- Preserved raw digit representations, including leading
  zeros and empty sequences.

#### `TritsChunk` and `DataTernary`

- Added direct decoding of `TritsChunk` values into
  fixed-size five-trit arrays.
- Replaced per-chunk `Ternary` constructions with direct
  balanced base-243 encoding and decoding.
- Optimized `DataTernary::from_ternary()` to avoid
  intermediate padded representations.
- Optimized `DataTernary::to_ternary()`,
  `to_fixed_ternary()`, and `to_digits()`.
- Implemented direct balanced base-243 conversions
  in `DataTernary::from_dec()` and `to_dec()`.
- Removed intermediate `Ternary` allocations from
  `DataTernary` formatting.
- Preserved chunk ordering, leading-zero padding,
  and empty storage behavior.

#### General

- Reduced unnecessary heap allocations and temporary
  representations across the library.
- Preserved `#![no_std]` compatibility.
- Introduced no breaking API changes in R07.

### Parsing and digit conversions (R08.1)

- Added const fallible `Digit::try_from_char()` and
  `Digit::try_from_i8()` constructors.
- Added `DigitConversionError`.
- Added `Ternary::try_parse()` and centralized balanced ternary parsing.
- Parsing explicitly preserves empty input and leading zeros.
- Parsing errors report the first invalid character and its UTF-8 byte offset.

- ### Bounded conversions (R08.2)

- Added `TernaryConversionError` and `ParseTryteError`.
- Added checked constructors for `Tryte<N>` and `TritsChunk`.
- Added borrowed and owned fallible conversions from `Ternary`
  to `Tryte<N>`, `TritsChunk`, and `Ter40`.
- Fixed conversions rejecting redundant leading zeros.
- Harmonized `Tryte<0>` conversions: zero is accepted,
  nonzero values are rejected.
- Implemented allocation-free `Tryte<N>` parsing.
- Parsing returns errors for numeric overflow and unsupported widths.

## Breaking Changes

### Fixed-width arithmetic

- `Tryte<N>` addition, subtraction, and multiplication now
  use wrapping arithmetic modulo `3^N`.
- Arithmetic overflow no longer causes a panic when using
  these operators.
- `Ter40` now strictly enforces its signed 40-trit range.
  Out-of-range construction and arithmetic results are rejected.

### Arbitrary-precision arithmetic

- `Ternary` arithmetic no longer relies on `i64`.
- Arithmetic results are normalized, removing leading zeros.
  Code relying on the previous representation of arithmetic
  results may observe different digit sequences.
- Division retains signed integer semantics with truncation
  toward zero, now supporting arbitrary-precision operands.

### Breaking changes — conversions

- Replaced `From<char>` and `From<i8>` for `Digit` with `TryFrom`.
- Replaced `From<&str>` and `From<String>` for `Ternary` with `TryFrom`.
- Changed `ParseTernaryError` from a unit struct to an enum.
- Existing explicit panicking constructors remain available.

### Breaking changes — bounded conversions

- Replaced fallible `From` implementations for `Tryte<N>`
  and `Ter40` with `TryFrom`.
- Changed `Tryte<N>::FromStr::Err` to `ParseTryteError`.
- Existing explicit panicking constructors remain available.

## API Compatibility

- Existing `DigitOperate` trait signatures remain unchanged.
- Existing arithmetic operator signatures remain unchanged.
- New checked, wrapping, overflowing, saturating, and modular
  arithmetic methods extend the public API.
- `Tryte<0>` remains supported, with conversion behavior
  subject to further review.

## Documentation

- Clarified numeric versus fixed-width arithmetic
  semantics across `Ternary`, `Ter40`, and `Tryte<N>`.
- Documented modular division and invertibility
  requirements.
- Documented arbitrary-precision arithmetic,
  quotient/remainder semantics, and overflow behavior.
- Updated implementation guidance and roadmap
  to reflect completed work through R06.
